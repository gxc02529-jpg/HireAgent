# 招聘场景复用说明

该仓库新增了招聘领域实现，参考已有项目中的设计模式，没有直接复制旅游业务查询、数据库连接配置、密钥或原始数据。下表中的路径是原有代码库名称，用于说明来源，运行 HireAgent 不依赖这些目录。

| 原有来源 | 可复用的设计 | HireAgent 中的实现 |
| --- | --- | --- |
| `agent_learn/01-function-call/C03_pydantic.py` | 参数模型、工具 Schema、工具名到实现的映射 | `domain.py` 定义严格参数；`tools.py` 生成 Schema 并统一校验调用 |
| `agent_learn/06-a2a-serial/main_orchestrator.py` | 按顺序执行职责独立的任务，错误中止后续步骤 | `agents.py` 将档案读取、岗位读取、匹配计算组成有事件轨迹的本地流程 |
| `agent_learn/02-mcp/03streamable/server_streamable.py` | 独立工具注册和对外描述 | `tools.py` 提供 13 个具名操作与输入 Schema；当前 HTTP 接口不是 MCP 协议 |
| `business_mcp_service/server.py` | 业务查询与工具层分离，返回结构化结果 | 招聘工具通过 `MemoryStore` 访问领域对象；没有复用旅游 SQL、搜索索引或数据库配置 |

## 招聘领域重新编写的部分

- 候选人与岗位模型、输入边界和合成样例。
- 技能/经验/地点的评分规则及逐项解释。
- 9 个明确意图到 3 个职责 Agent 的路由和调用权限。
- 候选人与面试官双边冲突、时区标准化、幂等键和取消语义。
- 并发安全的单进程内存仓库，以及 HTTP/SSE 接口和回归测试。

## 不能仅换业务名称复用的部分

旅游场景的天气、车票、租车、保险和旅行团工具与招聘数据结构不同；它们的 SQL、提示词和返回字段不能直接当作简历匹配或排期源码。原有 A2A/MCP 示例提供了后续网络集成方向，本仓库当前只实现本地 Agent 编排及 JSON 工具调用，未宣称已经具备 A2A 或 MCP 服务能力。

当前匹配分数是透明的演示规则，未通过真实招聘数据校准，也没有自动淘汰候选人或自动录用流程。人工可检查匹配证据后作出业务决定。
