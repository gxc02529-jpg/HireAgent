# 招聘场景平台复用与行业适配说明

该仓库体现“统一 Agent 交付底座 + 招聘行业模块”的拆分方式。通用底座负责工具契约、任务编排和事件输出，行业模块负责招聘领域模型、匹配规则、排期约束与评测样例；公开代码不包含客户数据、密钥或内部系统连接信息。

| 平台能力 | 可复用的设计 | HireAgent 中的实现 |
| --- | --- | --- |
| 结构化工具契约 | 参数模型、JSON Schema、工具名到实现的映射 | `domain.py` 定义严格参数；`tools.py` 生成 Schema 并统一校验调用 |
| Agent 编排接口 | 按顺序执行职责独立的任务，错误中止后续步骤 | `agents.py` 将档案读取、岗位读取、匹配计算组成有事件轨迹的本地流程 |
| 工具服务接口 | 独立工具注册和对外描述 | `mcp_server.py` 将 13 个领域操作注册为 FastMCP Tool，支持 STDIO 与 Streamable HTTP |
| 领域存储接口 | 业务查询与工具层分离，返回结构化结果 | 招聘工具通过 `MemoryStore` 访问领域对象，生产实现可替换为事务型 Repository |

## 招聘领域重新编写的部分

- 候选人与岗位模型、输入边界和合成样例。
- 技能/经验/地点的评分规则及逐项解释。
- 9 个明确意图到 3 个职责 Agent 的路由和调用权限。
- 候选人与面试官双边冲突、时区标准化、幂等键和取消语义。
- 并发安全的单进程内存仓库，以及 HTTP/SSE 接口和回归测试。

## 行业适配边界

招聘数据结构、评分证据、排期冲突和人工决策边界必须按领域重新实现，不能只替换业务名称。MCP 仅作为协议适配层并复用现有领域工具；A2A、LLM 推理、真实招聘系统连接和生产认证仍属于后续集成范围。

当前匹配分数是透明的演示规则，未通过真实招聘数据校准，也没有自动淘汰候选人或自动录用流程。人工可检查匹配证据后作出业务决定。
